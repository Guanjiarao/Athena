# 04-架构图

## 1. 主链路架构图

```text
[用户输入]
     ↓
[TriageController]
     ↓
[TriageOrchestratorServiceImpl]
     ↓
[TriageContext 创建 / 恢复]
     ↓
[TriageStateMachine]
     ↓
┌─────────────────────────────────────────────────────────┐
│ Parsing                                                 │
│ - TurnUnderstandingWorker                               │
│ - SemanticParserWorker                                  │
│ - FactExtractor                                         │
│ - StateReducer                                          │
│ - SlotManager                                           │
└─────────────────────────────────────────────────────────┘
     ↓
┌─────────────────────────────────────────────────────────┐
│ Validation                                              │
│ - QuestionPlanner                                       │
│ - SOPValidatorWorker                                    │
└─────────────────────────────────────────────────────────┘
     ↓
┌─────────────────────────────────────────────────────────┐
│ Risk / Report                                           │
│ - RiskStratifierWorker                                  │
│ - RiskHeuristicHelper                                   │
│ - TriageReplyBuilder                                    │
└─────────────────────────────────────────────────────────┘
     ↓
[最终响应]
```

## 3. 状态流转图

```text
turn-level observation
    ↓
TriageContext.latestTurnUnderstanding
    ↓
StateReducer
    ↓
StateReducerResult
    ↓
SlotManager
    ↓

```

## 4. 风险流转图

```text
原始输入 + slot state + extracted symptoms
    ↓
RiskTextSnapshotBuilder
    ↓
RiskHeuristicHelper
    ↓
RiskStratifierWorker
    ↓
TriageContext.riskAssessment / riskDecision
    ↓
QuestionPlanSupport / TriageStateMachine / TriageReplyBuilder
```

## 5. 这张图当前最重要的结论

### 已确认

- `TriageContext` 是中心状态容器
- parsing、validation、risk、reply 已经被拆成不同模块
- turn understanding 内部还有较宽的语义协调链

### 待验证

- 是否还需要继续把 turn understanding 里的协调职责再拆细
- risk layer 是否需要进一步显式化 semantic object

## 6. 一句话总结

从代码看，triage 现在已经是一个清晰的状态机编排系统，而不是单点模型调用系统。
