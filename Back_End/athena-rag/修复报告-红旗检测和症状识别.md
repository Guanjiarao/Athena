### 问题1：红旗检测过于敏感

**现象**：
- 用例7：用户明确回答"没有"呼吸困难，系统仍判定为红旗触发
- 用例8："有点喘"立即触发红旗，未评估严重程度

**根本原因**：
`RiskHeuristicHelper.java` 中的 `containsAny()` 方法只检查关键词是否存在，没有考虑：
1. 否定词（"没有"、"不"、"无"）
2. 轻度表达词（"有点"、"稍微"、"轻微"）

**修复方案**：
1. 新增 `containsAnySevere()` 方法，增强关键词检测逻辑
2. 检查关键词前10个字符内是否有否定词
3. 检查关键词前10个字符内是否有轻度表达词
4. 只有在没有否定词和轻度表达的情况下，才认为是严重症状

**修改文件**：
- `bootstrap/src/main/java/com/nageoffer/ai/ragent/triage/worker/RiskHeuristicHelper.java`

**修改内容**：
```java
// 新增方法
private boolean containsAnySevere(String text, List<String> keywords) {
    // 否定词列表
    List<String> negationWords = List.of("没有", "不", "无", "未出现", "未发生", "没");
    
    // 轻度表达词列表
    List<String> mildWords = List.of("有点", "稍微", "轻微", "一点点", "偶尔", "不太");
    
    // 检查关键词前10个字符内是否有否定词或轻度表达
    // 只有严重症状才返回 true
}

// 修改红旗检测调用
boolean dyspnea = hasRiskSignal(context, RiskSignalType.DYSPNEA)
    || hasResolvedYes(context, SlotCode.DYSPNEA_PRESENCE)
    || containsAnySevere(riskTextSnapshot.get(), List.of("呼吸困难", "喘不过气", ...));
```

**预期效果**：
- 用例7："没有呼吸困难" → 不触发红旗 ✓
- 用例8："有点喘" → 不触发红旗，继续收集信息 ✓
- 严重症状："喘不过气"、"呼吸困难" → 正常触发红旗 ✓

### 问题2：危险症状识别不足

**现象**：
- 用例5：用户说"黑便"、"油亮"，系统未识别为主诉
- 系统陷入重复询问"目前最明显的不适主要是什么"

**根本原因**：
`TurnUnderstandingExecutionEngine.java` 的规则提取逻辑中，缺少对消化道出血关键词的识别。

**修复方案**：
1. 在 `extractSymptomSlots()` 方法中新增危险症状关键词列表
2. 危险症状优先级最高，即使没有询问也直接提取为 PRIMARY_SYMPTOM
3. 包含的危险症状：
   - 消化道出血：黑便、柏油样便、油亮、血便、便血、呕血
   - 其他危重症状：胸痛、呼吸困难、意识不清、抽搐、惊厥

**修改文件**：
- `bootstrap/src/main/java/com/nageoffer/ai/ragent/triage/worker/TurnUnderstandingExecutionEngine.java`

**修改内容**：
```java
private List<AnsweredSlotUnderstanding> extractSymptomSlots(String input, List<SlotCode> lastAskedSlots) {
    // 危险症状关键词（优先级最高，即使没有询问也提取）
    String[] criticalSymptoms = {
        "黑便", "柏油样便", "油亮", "血便", "便血", "呕血", "咯血",
        "胸痛", "呼吸困难", "意识不清", "抽搐", "惊厥"
    };
    
    // 检查是否包含危险症状
    for (String critical : criticalSymptoms) {
        if (input.contains(critical)) {
            // 危险症状直接提取为 PRIMARY_SYMPTOM
            slots.add(createSlot(SlotCode.PRIMARY_SYMPTOM, input, normalizedValue, 
                AssertionStatus.PRESENT, 0.85, true));
            return slots; // 找到危险症状后立即返回
        }
    }
    
    // 普通症状处理逻辑...
}
```

**预期效果**：
- 用例5："黑便"、"油亮" → 立即识别为 PRIMARY_SYMPTOM ✓
- 避免重复询问主诉 ✓
- 快速进入风险评估流程 ✓

### 问题3：TRIGGER_WARNING 后缺少报告

**现象**：
- 用例7和8触发红旗后，建议科室得分为0
- 响应中缺少 recommendedDepartment 字段

**根本原因**：
`TriageOrchestratorServiceImpl.java` 的 `toWarningResponse()` 方法只返回警告文本，没有生成完整报告。

**修复方案**：
1. 在 `toWarningResponse()` 中调用科室推荐引擎
2. 对于高风险（level >= 3），强制推荐急诊科
3. 在 `TriageWarningData` 中添加 recommendedDepartment 和 departmentReason 字段

**修改文件**：
- `bootstrap/src/main/java/com/nageoffer/ai/ragent/triage/service/impl/TriageOrchestratorServiceImpl.java`
- `bootstrap/src/main/java/com/nageoffer/ai/ragent/triage/controller/vo/TriageWarningData.java`

**修改内容**：

1. TriageOrchestratorServiceImpl.java：
```java
private TriageAnalyzeResponse toWarningResponse(TriageContext context) {
    // 使用科室推荐引擎
    DepartmentRecommender recommender = new DepartmentRecommender();
    DepartmentRecommender.DepartmentRecommendation recommendation = recommender.recommend(context);
    
    // 如果风险等级 >= 3，强制推荐急诊科
    if (context.getRiskAssessment() != null && context.getRiskAssessment().getLevel() >= 3) {
        recommendation = new DepartmentRecommender.DepartmentRecommendation(
            "急诊科",
            "存在高风险症状，建议立即前往急诊科就诊"
        );
    }
    
    TriageWarningData data = TriageWarningData.builder()
        // ... 其他字段
        .recommendedDepartment(recommendation.getDepartment())
        .departmentReason(recommendation.getReason())
        .build();
    // ...
}
```

2. TriageWarningData.java：
```java
@Schema(description = "推荐就诊科室")
private String recommendedDepartment;

@Schema(description = "科室推荐理由")
private String departmentReason;
```

**预期效果**：
- 触发红旗时，返回完整报告 ✓
- 包含风险等级、建议科室（急诊科）、简要分析 ✓
- 评测时建议科室得分不为0 ✓
