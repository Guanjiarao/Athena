# 03-v2-重构与演进

## 1. 为什么要有 v2

v1 的问题不是“功能少”，而是职责开始混叠：

- 主诉真相不单一
- correction 同时承担 parsing / resolution / application
- risk 只有 signal 和 decision，缺少稳定语义层
- planner 会回退到过于底层的 slot-first 逻辑
- `TurnUnderstandingWorker` 过载

v2 的目标不是把类名改得更好看，而是把 source of truth 和职责边界重新拍直。

## 2. v2 的核心原则

### 2.1 先稳主诉，再稳 correction，再稳 risk

这是迁移顺序，不是终态偏好。

### 2.2 turn-level 只产候选，session-level 才产真相

这是整个架构最重要的分层。

### 2.3 worker 负责观察，不负责最终写 truth

worker 可以解析、提取、标记、归类，但不应顺手做 session truth 的最终拍板。

### 2.4 reducer 负责归约，不负责扩张策略

reducer 的角色是合并状态，不是发明新的问诊策略。

### 2.5 planner 只消费稳定状态

planner 不应再直接依赖摇摆的 turn-level 临时值。

## 3. 当前 v2 的阶段化思路

根据 `docs/重构计划/` 的方案，v2 采用分阶段迁移：

### Phase 1：投诉候选、follow-up 回答、纠正短语从大 worker 中切出

目标：
- 稳住主诉输入
- 让 complaint carry 回到 reducer
- 让最基础的文本观察层与状态层分离

### Phase 2：纠正目标解析与纠正消费回到 state 层

目标：
- 让 correction 不再由 worker 顺手拍板
- 让主诉修正和 slot 修正走统一框架

### Phase 3：建立 risk semantic layer

目标：
- 让 risk 从“信号 + 决策”变成“信号 + 语义 + 动作”
- 让 planner 直接消费稳定的 risk concern

## 4. 当前主控对 v2 的判断方式

v2 不是一口气重写完成的，而是通过控制切口来推进。

因此，每一轮的判断都应该问：

- 这刀切的是不是单一边界
- 有没有打坏已有稳定线
- 有没有把 truth 写回错误层
- 是否能为下一刀提供更稳定的输入

## 5. 当前已经看见的 v2 现实切口

从主控记录和开发报告看，近期有一个很典型的切口：

- 先修 `duration extraction / answered-slot grounding`
- 不先动 planner
- 不先开 risk semantic layer
- 先让用户已经说出的持续时间稳定进入 `DURATION`

这个切口体现的是 v2 的典型思路：

1. 不扩大范围
2. 先修上游地基
3. 让下游 planner 在正确输入上工作

## 6. v2 与当前代码的关系

当前代码并不是“旧代码等待推翻”，而是：

- 一部分已经符合 v2 方向
- 一部分仍带有 v1 兼容逻辑
- 一部分正在通过窄切口渐进演化

因此，v2 的落地不是“重写一个新系统”，而是：
- 把旧系统中最乱的职责边界一点点拉直
- 让现有类在新边界下逐渐退化成更纯的角色

## 7. 一句话总结

v2 的本质是：把分诊台从“能跑但职责混乱”推进到“能跑且 source of truth 清晰”的状态。
