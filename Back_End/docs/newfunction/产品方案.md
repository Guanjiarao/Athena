以下是整合后的 Athena 产品方案 V2。它保留原方案的完整闭环，同时正式加入冷启动、用户调性、可信内容、隐私、低负担交互和版本收缩，并移除“广场”。

当前仍只确定方案，不修改代码、不调整配色。

# 一、产品总定位

Athena 不是经期工具、科普平台、AI聊天助手或收藏夹，而是：

> 帮助女性记住身体变化、发现个人规律，并知道下一步该观察、了解或处理什么的个人身体认知系统。

内部产品定义可以使用“个人身体认知系统”，但面对用户应使用更直接的表达：

> 不只记录经期，也帮你理解身体为什么这样变化。

Athena 的核心价值不是提供网上也能搜到的知识，而是将以下信息长期连接：

- 用户确认的身体记录；
- 周期和设备数据；
- 用户提出的疑问；
- 用户标记的可信内容；
- 当前人生阶段与健康目标；
- 后续行动和反馈结果。

最终形成：

```text
身体变化或困惑
→ 低成本记录、阅读、提问
→ Athena 发现值得关注的线索
→ 用户确认认知主题
→ Athena 解释依据与不确定性
→ 给出一个具体行动
→ 用户执行并反馈
→ 系统更新判断和内容推荐
→ 形成长期个人规律
```

# 二、目标用户与首期边界

第一阶段核心用户收缩为：

> 18～30 岁、缺少系统女性健康教育、存在周期或身体困惑，但尚未形成稳定记录习惯的年轻女性。

核心问题包括：

- 这个身体变化正常吗？
- 它是否与周期有关？
- 我应该继续观察还是寻求帮助？
- 网上说法很多，哪些值得相信？
- 我记录过很多次，但看不出规律。

第一阶段不同时覆盖未成年人、孕期、疾病治疗、围绝经期等高差异场景。备孕、避孕可以作为关注主题，但不立即建设完整医疗方案。

女性用户不是统一群体，产品表达必须避免：

- 默认用户有异性伴侣；
- 默认用户追求生育；
- 用“女孩”“宝宝”等称呼弱化用户；
- 把经期描绘成羞耻或麻烦；
- 用健康评分制造自律压力；
- 用过度拟人化的 AI 假装亲密；
- 把粉色、柔弱和女性感直接等同。

Athena 的整体调性应是：

> 克制、清醒、尊重、私密、有解释力，但不冷漠。

# 三、产品整体结构

底部导航调整为：

```text
健康
知识
我的
```

“广场”从导航栏中移除，暂不进入本轮建设范围。

后续实际修改时：

- 移除广场导航入口；
- 不删除广场已有代码和数据；
- 不破坏未来恢复能力；
- 不让广场内容进入健康预测和认知主题。

AI不设置成孤立导航页，而是贯穿健康、知识和我的三个模块。

# 四、三个模块的职责

## 1. 健康

健康成为默认首页，负责：

- 展示今天的个人身体状态；
- 展示 Athena 是否发现了变化；
- 推进正在观察的认知主题；
- 给出一个低负担行动；
- 提供快捷记录；
- 进入周期日历、历史记录和分析；
- 建立用户每天回访的理由。

## 2. 知识

知识负责可信解释和内容输入：

- 搜索文章和视频；
- 推荐与当前主题有关的内容；
- 展示推荐原因；
- 支持文章标记和提问；
- 将标记送入“我的身体线索”；
- 用可信内容承接用户疑问。

知识页不再是默认首页，也不能做成无限信息流。

## 3. 我的

“我的”是用户的个人认知空间，负责：

- 我的身体认知；
- 我的身体线索；
- 我的疑问；
- Athena 整理草稿；
- 历史行动与反馈；
- 提醒偏好；
- 我的数据与隐私；
- 其他个人设置。

原“数据资产”入口和渲染区域后续删除，但保留底层数据，并在设置中保留更易理解的“我的数据与隐私”。

# 五、冷启动设计

原方案依赖长期记录，首次用户无法立即获得价值，因此必须设计三个价值周期：

| 时间 | 用户获得的价值 |
|---|---|
| 首次使用 3 分钟 | 得到一个与当前困惑相关的可信回应 |
| 前 7 天 | 感受到记录、知识与个人问题开始连接 |
| 2～3 个周期 | 看到属于自己的重复规律和变化 |

首次进入时不填写完整健康档案，只询问：

```text
最近你最想弄清哪件事？

经期是否规律
某种不适是否正常
情绪和周期是否有关
避孕与性健康
只是想更了解身体
```

用户选择后，Athena 立即提供：

- 一句初步解释；
- 一项今天可以完成的记录；
- 一篇可信内容；
- 一个后续观察时间点。

这会形成第一个轻量观察主题，但不会立即形成健康结论。

# 六、健康首页设计

大日历不再占据首页，降级为二级工具。健康首页先回答：

> 我今天怎么样？Athena 发现了什么？我现在能做什么？

首页结构调整为：

```text
顶部日期与状态
→ 今日身体状态
→ Athena 最新发现或平静反馈
→ 正在理解的一个主题
→ 今日下一步
→ 快捷记录
→ 日历、历史记录和设备数据入口
```

## 首页三种模式

### 平静模式

没有值得处理的变化时，不强行生成 AI 发现：

```text
今天没有需要特别处理的变化

你正处于周期第 12 天，
最近记录仍在你的个人范围内。
```

### 观察模式

存在正在跟进的问题：

```text
正在观察：经期前情绪变化

目前存在初步联系，
今天可以记录一次睡眠和情绪状态。
```

### 留意模式

规则发现明确变化：

```text
最近两个周期的疼痛持续时间有所增加。

这并不代表已经出现疾病，
但值得继续记录，必要时寻求专业帮助。
```

风险状态不能依靠颜色和分数表达，也不能制造焦虑。

## 首页核心区域

首页只突出：

- 一个最值得关注的认知主题；
- 一个下一步行动；
- 一条有依据的变化提示。

不要同时展示多个长报告、多个行动和大量文章。

快捷记录包括：

```text
身体
情绪
睡眠
周期
其他
```

记录完成后说明用途：

> 已记录。这条信息会帮助 Athena 继续观察“经期前情绪变化”。

日历保留为：

```text
查看周期日历
查看历史记录
```

# 七、认知主题系统

认知主题是连接健康、知识、记录、AI和反馈的中枢。

主题应是具体个人问题，而不是宽泛分类，例如：

- 经期前情绪变化；
- 最近周期变长；
- 反复出现的乳房胀痛；
- 睡眠与身体状态；
- 经期疼痛；
- 我正在了解的避孕方式。

## 主题页结构

分析报告不再是一篇长报告，而是在页眉展示主题标签：

```text
周期规律
经前情绪
睡眠变化
乳房胀痛
+3
```

点击后切换对应主题。

主题详情包含：

```text
当前理解
判断依据
可能的联系
还不能确定什么
下一步行动
相关可信内容
最近变化
用户反馈
历史版本
```

首页只展示一句摘要，详情页才展开依据。

## 状态体系

后端保留三条并行维度：

```text
认知成熟度：
线索 → 信息不足 → 初步联系 → 重复规律 → 相对稳定

用户进度：
待确认 → 正在关注 → 正在观察 → 暂停 → 已归档

风险状态：
无明显风险 → 需要留意 → 建议专业帮助
```

前端不直接暴露这些系统术语，转换成：

```text
刚刚记下
还需要了解
可能存在联系
多次出现
已形成个人规律
```

AI不能自行宣布形成规律、问题已解决或用户患有某种疾病。

# 八、主题创建机制

主题分为：

```text
线索
→ 候选主题
→ 正式主题
```

以下情况可形成候选主题：

- 用户明确确认自己出现过某种情况；
- 不同日期出现两次相近记录；
- 同一情况跨两个周期重复；
- 一条身体记录加一条相关标记或疑问；
- 用户主动选择持续观察；
- 用户主动要求 Athena 整理。

正式主题必须经用户确认：

```text
你最近两次记录了经期前头痛。
要让 Athena 帮你继续观察吗？

开始观察
暂时不用
```

AI可以发现候选、推荐归类和生成草稿，但不能把阅读行为、疑问或收藏直接变成身体事实。

# 九、文章详情与低负担标记

文章标记不能成为强制复杂流程，采用渐进式交互。

## 第一次标记

用户选中文字后快速选择：

```text
和我有关
想弄明白
收藏
```

一步完成，不立即要求填写详细信息。

## 再次出现相关线索

系统轻量询问：

```text
你标记的几段内容似乎都与经期疼痛有关。
这是你亲身出现过的情况吗？
```

## 准备建立候选主题时

再进入专门页面：

```text
这和我的身体有什么关系？

我现在有类似情况
以前出现过
我不确定，但想观察
只是觉得值得了解
```

随后选择：

```text
帮我持续观察
帮我找可信知识
帮我了解是否需要留意
暂时只保存
```

时间、程度、是否与周期相关等信息全部可跳过。

这样既保留完整结构，又不把整理负担全部交给用户。

# 十、我的身体线索

“我的”中新增正式入口：

> 我的身体线索

分为：

```text
待整理
已整理
我的疑问
```

必须区分：

- 用户阅读过的知识；
- 用户确认过的身体经历；
- 用户仍想弄明白的问题。

待整理内容展示原文、来源、标记原因和归类状态。

已整理内容按认知主题聚合，不按文章聚合。

我的疑问只表示用户关心某个问题，不代表用户具有对应症状。

# 十一、AI自动整理

第一版触发条件：

```text
同一主题至少 3 条有效标记
或
2 条有效标记 + 1 条身体记录
或
用户主动点击“帮我整理”
```

同时检查：

- 内容是否语义相近；
- 来源是否可信；
- 是否存在重复内容；
- 是否包含用户确认的经历；
- 用户是否暂停观察；
- 是否触及高风险边界。

AI先生成整理草稿：

```text
你最近标记的内容主要围绕：
经期前情绪变化

共同点：
……

与你可能有关的原因：
……

目前还不能确定：
……

加入正在观察
只保存为知识
这不是我想表达的
```

用户确认后才形成正式主题。

默认按主题整理，同时提供“整理全部”，但不同问题不得混合生成结论。

# 十二、提前提醒与内容推荐

产品对外不强调“AI预测”，改为：

- 提前提醒；
- 趋势预判；
- 可能的重复；
- 值得留意的变化。

分工保持：

> 规则和统计模型发现信号，AI解释和组织表达，用户反馈校正系统。

高权重输入：

- 用户确认的记录；
- 周期历史；
- 正式认知主题；
- 用户目标；
- 可靠的设备数据。

低权重输入：

- 文章标记；
- 用户疑问。

不能用于健康判断：

- 浏览历史；
- 点赞；
- 普通收藏。

每条提醒必须包含：

```text
发现了什么
依据是什么
还不确定什么
下一步做什么
```

同时允许用户反馈：

```text
准确
不太准确
这次没有发生
不想再收到此类提醒
```

默认限制：

- 每天最多一条普通健康提醒；
- 每周最多两次认知更新；
- 用户可暂停某类提醒；
- 风险边界提示必须由明确规则触发。

内容推荐顺序为：

```text
个人状态提示
→ 一项行动
→ 一篇文章或一个视频
```

# 十三、知识可信度

知识模块必须把“可信”做成显性能力。

每篇健康内容展示：

- 来源；
- 审核身份；
- 最近更新时间；
- 适用人群；
- 内容依据；
- 存在争议的部分；
- 何时需要专业帮助。

推荐内容应允许查看：

> 为什么推荐给我？

例如：

> 因为你正在观察“经期前情绪变化”，不是因为你浏览过疾病内容。

AI只使用审核后的内容库生成健康解释，不直接使用开放网络内容形成个人健康结论。

# 十四、隐私原则

隐私不是附加设置，而是 Athena 的产品竞争力。

用户必须知道：

- 哪些数据保存在本地；
- 哪些数据上传服务器；
- 哪些信息会交给 AI；
- 为什么需要这些信息；
- 是否用于模型训练；
- 如何关闭个性化；
- 如何删除、撤回和导出；
- 关闭提醒是否影响记录；
- 哪些信息绝不会被公开。

“数据资产”删除后，在设置中保留：

> 我的数据与隐私

不得默认公开任何身体记录、疑问和认知主题。

# 十五、Agent 工作流

第一版采用受约束的任务流水线：

```text
记录 / 标记 / 提问
→ 意图识别
→ 主题匹配
→ 规则与统计信号检测
→ 判断是否需要整理
→ 组织证据
→ AI生成摘要、问题和行动
→ 安全校验
→ 用户确认
→ 更新主题
→ 安排后续复盘
```

AI负责：

- 意图分类；
- 主题语义匹配；
- 内容整理；
- 易懂表达；
- 待确认问题；
- 合格内容排序。

规则系统负责：

- 风险边界；
- 趋势阈值；
- 推送频率；
- 证据充分性；
- 是否允许进入下一状态。

用户负责：

- 确认身体事实；
- 修正错误归类；
- 决定是否继续观察；
- 反馈提醒是否准确；
- 决定主题是否结束。

# 十六、第一版建设范围

为了真正验证闭环，第一版只主攻：

- 三项底部导航；
- 新健康首页；
- 首页平静、观察、留意三种模式；
- 快捷记录；
- 一个完整认知主题；
- 主题详情标签结构；
- 文章快速标记；
- 我的身体线索；
- AI整理草稿；
- 一项行动；
- 一次后续复盘；
- 一种规则驱动的提前提醒；
- 可信文章来源与推荐理由；
- 数据与隐私入口。

第一版暂不主攻：

- 广场；
- 高度自主的多 Agent；
- 大规模视频算法；
- 多人生阶段完整模型；
- 复杂设备数据分析；
- 多主题因果推断；
- 疾病诊断和治疗建议。

这些不是永久删除，而是在核心闭环成立后逐步增加。

# 十七、前后端分工

前端先用模拟数据实现：

- 完整用户路径；
- 页面状态；
- 用户确认；
- 错误纠正；
- 空态；
- AI等待和失败；
- 提醒反馈；
- 主题暂停与归档。

后端负责：

- 数据保存；
- 规则引擎；
- 主题匹配；
- AI任务；
- 内容检索；
- 推送任务；
- 风险校验；
- 版本记录；
- 权限与隐私。

双方先确定稳定数据契约，前端不依赖数据库字段细节。

# 十八、实施顺序

第一步，修改导航和搭建健康首页，先完成冷启动、三种首页状态和二级日历入口。

第二步，完成认知主题详情、文章快速标记和“我的身体线索”，跑通前端模拟闭环。

第三步，加入 AI 整理草稿、下一步行动、用户反馈和提前提醒。

第四步，整理后端数据模型、接口、Agent任务、规则阈值、内容可信度和隐私要求。

第五步，接入真实后端并验证完整闭环：

```text
提出困惑或记录身体
→ 建立观察主题
→ 获得可信解释
→ 完成一次行动
→ 后续反馈
→ Athena 更新阶段理解
```

# 十九、核心成功指标

第一阶段不以阅读量和收藏量作为核心指标，而应观察：

- 首次使用是否建立一个观察主题；
- 用户是否完成第一个行动；
- AI整理结果确认率；
- AI错误归类率；
- 后续反馈率；
- 两个周期持续观察率；
- 提醒准确反馈率；
- 提醒关闭率；
- 用户是否认为自己更理解身体；
- 用户是否知道何时应继续观察、何时应寻求帮助。

最终，Athena 的三个用户承诺是：
