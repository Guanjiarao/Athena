# Athena Cognition Agent Workflow V1

This package is the second-handoff artifact described by the V2.1 product plan. It has no model
key, database access, Android dependency, or deployment code.

The Agent replaces only the `DigestGenerator` implementation. The backend remains responsible for
authentication, user isolation, eligible-input assembly, idempotency, retries, JSON Schema
validation, persistence, evidence links, and the user confirmation transaction.

## Safety boundary

- Article marks and questions are low-weight context, not body facts.
- Browsing, likes, collections, and community content are forbidden inputs.
- A digest is never a diagnosis and cannot create a topic by itself.
- `riskStatus` is not generated by this workflow. Only an auditable backend rule may change it.
- Model output is rejected unless every statement references provided evidence and uncertainty is explicit.
- Full prompts, excerpts, questions, body notes, and model output must not be logged.

## Contents

- `workflow.md`: nodes, thresholds, failure paths, and handoff responsibilities.
- `prompts/`: model system and task instructions.
- `schemas/`: versioned JSON input/output contracts.
- `fixtures/`: correct, boundary, and unsafe test inputs.
- `examples/`: accepted structured output and rejected-output explanations.
- `prototype.py`: deterministic local prototype; it makes no network request.

Run the local prototype from the repository root:

```bash
python agent-workflow/prototype.py agent-workflow/fixtures/related-and-question.json
```
