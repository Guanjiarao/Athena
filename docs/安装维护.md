# Athena 双端系统安装与维护手册

## 1. 文档说明

本文档用于说明 Athena 项目的本地安装、开发运行、构建打包、配置检查、日常维护、故障排查和版本发布注意事项。适用对象包括开发人员、测试人员、部署维护人员和项目交付人员。

本文档覆盖两个前端工程：

- 管理员网站端：`admin_web_front`
- Android 用户端：`athena_app_front`

后端微服务的部署、数据库、注册中心、网关、RAG 服务和对象存储等内容，请结合《架构文档.md》和后端项目部署说明执行。本文档重点说明当前仓库中两个前端工程的安装与维护。

## 2. 环境要求

### 2.1 通用要求

- 操作系统：Windows 10/11、macOS 或 Linux 均可，当前项目路径示例基于 Windows。
- 网络：首次安装依赖、Gradle 同步、下载 Android SDK 或访问 Maven 仓库时需要稳定网络。
- Git：建议安装 Git，用于版本管理和变更核对。
- 后端服务：联调时应确认后端网关、认证、内容、文件、AI、记录等服务可访问。

### 2.2 Web 管理端环境

| 项目 | 要求 |
| --- | --- |
| Node.js | 建议 18 或更高版本 |
| npm | 随 Node.js 安装 |
| 浏览器 | Chrome、Edge 或其他现代浏览器 |
| 构建工具 | Vite |

Web 端关键依赖包括 React、TypeScript、React Router、Axios、Tailwind CSS、react-quill-new 等。依赖版本以 `admin_web_front/package.json` 和 `package-lock.json` 为准。

### 2.3 Android App 环境

| 项目 | 要求 |
| --- | --- |
| Android Studio | 建议使用稳定版本 |
| JDK | 项目 Java 编译目标为 Java 8，Android Studio 自带 JDK 通常可用 |
| Android SDK | compileSdk 36、targetSdk 36 |
| 最低系统版本 | minSdk 24，即 Android 7.0 |
| 构建工具 | Gradle Wrapper |
| 测试设备 | Android 7.0 及以上真机或模拟器 |

App 端关键依赖包括 AppCompat、Material Components、ConstraintLayout、RecyclerView、OkHttp、Gson、Glide、Markwon、ML Kit、GSYVideoPlayer、HeyTap Health SDK 等。依赖版本以 `athena_app_front/app/build.gradle.kts` 和版本目录配置为准。

## 4. Web 管理端安装与运行

### 4.1 安装依赖

进入 Web 工程目录：

```bash
cd admin_web_front
npm install
```

建议：

- 如已有 `package-lock.json`，应优先使用它保持依赖版本一致。
- 如果依赖安装失败，先检查 Node.js 版本、npm 源和网络代理。
- 不建议手工删除锁文件后随意升级依赖，除非明确需要升级并完成回归测试。

### 4.2 启动开发环境

```bash
npm run dev
```

启动后根据终端输出访问本地地址，通常为：

```text
http://localhost:5173
```

如端口被占用，Vite 可能自动切换端口，应以终端实际输出为准。

### 4.3 生产构建

```bash
npm run build
```

该命令会先执行 TypeScript 构建检查，再执行 Vite 打包。构建产物通常输出到 `dist` 目录。

构建前应确认：

- 依赖已完整安装。
- TypeScript 类型错误已处理。
- 后端接口地址和代理配置符合目标环境。
- 登录、审核、发布、内容管理、上传等关键流程已完成测试。

### 4.4 预览构建结果

```bash
npm run preview
```

该命令用于本地预览生产构建产物，适合在发布前进行快速验证。

### 4.5 Web 端常用脚本

| 命令 | 说明 |
| --- | --- |
| `npm install` | 安装依赖 |
| `npm run dev` | 启动开发环境 |
| `npm run build` | 构建生产产物 |
| `npm run preview` | 本地预览构建产物 |
| `npm run lint` | 执行代码检查 |

## 5. Android App 安装与运行

### 5.1 导入项目

1. 打开 Android Studio。
2. 选择 `Open`。
3. 选择项目目录 `athena_app_front`。
4. 等待 Gradle Sync 完成。
5. 确认 `:app` 模块可被识别。

首次导入时间可能较长，取决于 Gradle、Android SDK、Maven 仓库和网络情况。

### 5.2 Gradle 同步要求

项目使用 Gradle Wrapper，建议优先使用项目自带脚本。

Windows：

```bash
cd athena_app_front
.\gradlew.bat :app:assembleDebug
```

macOS / Linux：

```bash
cd athena_app_front
./gradlew :app:assembleDebug
```

如果 Gradle 同步失败，应检查：

- Android SDK 是否安装完整。
- JDK 是否可用。
- `google()`、`mavenCentral()`、`jitpack.io` 等仓库是否可访问。
- 第三方健康 SDK 仓库是否可访问。
- 本地网络代理或证书配置是否影响依赖下载。

### 5.3 运行 App

运行方式：

1. 连接 Android 真机或启动模拟器。
2. 在 Android Studio 中选择 `app` 配置。
3. 点击运行。
4. 首次运行时按系统提示授予必要权限。

建议使用真机验证以下能力：

- 相册或文件选择。
- 图片上传。
- 视频播放。
- OCR 识别。
- 私密图库。
- 健康设备或健康 SDK 相关能力。

### 5.4 构建调试包

```bash
cd athena_app_front
.\gradlew.bat :app:assembleDebug
```

调试包通常用于联调和测试。生成位置一般在：

```text
athena_app_front/app/build/outputs/apk/debug/
```

### 5.5 构建发布包

```bash
cd athena_app_front
.\gradlew.bat :app:assembleRelease
```

发布包构建前应确认：

- 签名配置已按发布要求准备。
- 生产接口地址已确认。
- 第三方 SDK、视频播放、OCR、AI、文件上传等能力完成回归。
- 敏感配置和密钥未错误写入公开文档或日志。

当前项目 `release` 配置中 `isMinifyEnabled` 为 `false`。如后续启用混淆，需要维护 `proguard-rules.pro`，并重点验证反射、JSON 解析、第三方 SDK、视频播放和 OCR 相关功能。

## 6. 配置维护

### 6.1 Web 管理端配置检查

Web 端维护重点：

- `package.json`：依赖和脚本。
- `src/api/axios.ts`：统一请求实例、Token 注入和响应异常处理。
- `src/contexts/AuthContext.tsx`：登录状态、角色和本地会话。
- `src/App.tsx`：路由、权限守卫和角色跳转。
- `src/api/*`：审核、发布、上传、内容管理等接口封装。
- `src/lib/*`：分类映射、常量和内容处理工具。

配置变更时应检查：

- 后端接口路径是否变化。
- 鉴权 Header 是否仍使用 `Authorization: Bearer <token>`。
- 管理员和发布者角色是否仍为系统约定值。
- 构建脚本是否仍可执行。
- 发布前是否已清除不必要的调试日志。

### 6.2 Android App 配置检查

App 端维护重点：

- `app/build.gradle.kts`：SDK 版本、依赖、构建配置。
- `settings.gradle.kts`：Maven 仓库配置。
- `AndroidManifest.xml`：Activity、权限、文件访问等配置。
- `config/ApiConfig.java`：后端接口地址、超时时间和接口路径。
- `utils/TokenManager.java`：Token 读取、更新和 userId 解析。
- `core/RagSseClient.java`：AI SSE 流式请求和事件解析。
- `utils/UploadUtil.java`：文件上传。
- `features/privacy/*`：隐私、OCR、本地脱敏相关能力。

配置变更时应检查：

- API 基础地址是否指向正确环境。
- Android SDK、Gradle 插件和依赖版本是否兼容。
- 第三方 Maven 仓库是否可访问。
- 网络明文访问、文件共享路径、权限声明是否满足目标 Android 版本要求。
- Token、用户 ID、登录态是否能正常保存和恢复。

### 6.3 敏感配置维护

维护原则：

- 不应将生产密钥、长期有效 Token、第三方私密凭证写入公开文档。
- 如仓库中存在历史测试密钥或第三方仓库凭证，应限制访问范围，并在正式交付前评估是否需要迁移到安全配置渠道。
- 运行日志不应输出完整 Token、手机号、身份证号、病历内容、私密图片路径等敏感信息。
- AI、OCR、隐私上传等功能应特别注意请求参数和日志内容。

## 7. 后端联调检查

两个前端均依赖后端网关和多个业务服务。联调前应确认后端具备以下能力：

| 能力 | 相关服务 | 前端影响 |
| --- | --- | --- |
| 登录认证 | `athena-userauth` | Web/App 登录、Token 获取 |
| 内容列表与详情 | `athena-ground` | 推荐、知识、广场、详情 |
| 内容审核与管理 | `athena-ground` 管理接口 | Web 审核、内容管理 |
| 评论回复 | `athena-comment` | App 评论区 |
| 关注粉丝 | `athena-relation` | App 关注、粉丝列表 |
| 文件上传 | `athena-oss` | 头像、图片、视频上传 |
| 经期与健康记录 | `athena-record` | 记录模块、日历和统计 |
| 分析报告 | `athena-insight` | App 分析报告 |
| AI/RAG | `athena-rag` | AI 问答、SSE 流式回复 |

联调建议：

- 先验证登录接口，再验证依赖登录态的功能。
- 先验证文件上传，再验证内容发布。
- 先验证内容详情，再验证评论、点赞、收藏。
- 先验证健康记录保存，再验证分析报告。
- AI 功能应单独验证普通回答、流式输出、错误处理和引用内容。

## 8. 日常维护流程

### 8.1 接口变更维护

后端接口发生变化时，应按以下流程处理：

1. 明确接口变更范围，包括路径、请求方法、请求参数、返回字段和错误码。
2. 更新 Web 端 `src/api/*` 或 App 端 `ApiConfig.java`、对应 `ApiService`。
3. 检查 Token 注入、分页参数、文件上传字段是否受影响。
4. 回归对应页面和相关上下游流程。
5. 更新需求、设计、架构或使用文档中的相关描述。

### 8.2 新增功能维护

新增功能时应同步维护：

- 页面入口或导航入口。
- 路由或 Activity/Fragment 声明。
- 接口定义和数据模型。
- 权限和登录态判断。
- 加载、空状态、失败状态。
- 日志、异常处理和回归测试用例。
- 相关文档。

### 8.3 依赖升级维护

依赖升级前应评估：

- 是否存在破坏性变更。
- 是否影响构建脚本。
- 是否影响 Android SDK、Gradle、JDK 或 Node.js 版本。
- 是否影响图片加载、视频播放、OCR、AI、上传等关键能力。

升级后至少回归：

- Web 登录、审核、发布、上传、内容管理。
- App 登录、内容列表、详情、评论、发布、AI、记录、隐私、视频播放。

### 8.4 文档维护

文档维护要求：

- 需求变化更新《需求规格.md》。
- 模块设计变化更新《功能设计.md》。
- 架构或目录变化更新《架构文档.md》。
- 页面操作和截图变化更新《使用手册.md》。
- 安装步骤、依赖、配置、排障变化更新本文档。

## 9. 日志与排障

### 9.1 Web 端排障

常用检查点：

- 浏览器控制台 Console 是否有 JavaScript 错误。
- Network 面板中接口路径、请求方法、状态码和响应体是否正确。
- `Authorization` 请求头是否存在。
- localStorage 中登录会话是否存在且结构正确。
- 页面路由是否因角色不匹配被重定向。
- 文件上传请求是否成功返回资源 URL。

常见问题：

| 问题 | 可能原因 | 处理建议 |
| --- | --- | --- |
| 登录后仍跳回登录页 | Token 未保存或会话读取失败 | 检查 `AuthContext` 和 localStorage |
| 审核页无数据 | 接口失败、无待审核内容或权限不足 | 检查 Network 和后端返回 |
| 上传失败 | 文件过大、类型不支持或 OSS 服务异常 | 检查上传接口响应 |
| 发布失败 | 必填字段缺失或接口参数变化 | 检查表单校验和请求体 |
| 权限跳转异常 | 用户角色字段变化 | 检查登录返回角色值 |

### 9.2 Android App 排障

常用检查点：

- Android Studio Logcat。
- 网络请求 URL、状态码和响应体。
- `ApiConfig.java` 中接口地址。
- 本地 Token 是否保存成功。
- AndroidManifest 权限是否声明。
- 运行时权限是否授予。
- 图片、视频、OCR、AI 相关依赖是否加载成功。

常见问题：

| 问题 | 可能原因 | 处理建议 |
| --- | --- | --- |
| App 启动后未显示主导航 | 本地 Token 不存在或登录态失效 | 重新登录并检查本地存储 |
| 内容列表为空 | 接口异常、分类参数错误或网络失败 | 检查 `ApiConfig` 和 Logcat |
| 图片不显示 | URL 无效、网络失败或 Glide 加载失败 | 检查图片地址和网络权限 |
| 视频无法播放 | 视频 URL 异常或播放器依赖问题 | 检查资源地址和 GSYVideoPlayer 日志 |
| AI 无回复 | RAG 服务异常、SSE 解析失败或 Token 无效 | 检查 `RagSseClient` 日志和接口响应 |
| OCR 不工作 | ML Kit 依赖缺失或图片读取失败 | 检查权限和模型依赖 |
| 上传失败 | 文件路径、权限或上传服务异常 | 检查文件选择和上传响应 |

### 9.3 后端联调排障

当前端功能异常但页面逻辑无明显问题时，应进一步检查：

- 网关服务是否可访问。
- Token 是否过期。
- 后端是否返回统一错误结构。
- 服务是否注册到 Nacos。
- 文件服务、RAG 服务、记录服务是否独立可用。
- 跨服务调用是否出现异常。

## 10. 数据备份与清理

### 10.1 Web 端本地数据

Web 端主要本地数据包括：

- 登录会话：localStorage 中的 `athena-auth-session`。
- 临时 Token：可能存在历史兼容字段 `token`。

维护建议：

- 排查登录问题时可清理浏览器 localStorage 后重新登录。
- 不应在生产环境手工修改浏览器存储中的 Token 和角色。

### 10.2 App 端本地数据

App 端本地数据包括：

- 登录用户和 Token。
- 搜索历史。
- 内容缓存。
- AI 会话历史。
- 周期设置。
- 私密图库本地文件。
- 健康记录相关本地缓存。

维护建议：

- 测试环境可通过卸载 App 清理本地数据。
- 排查登录和缓存问题时，可清除应用数据后重新登录。
- 私密图库和健康数据涉及隐私，测试后应按要求清理。

### 10.3 后端数据

后端数据备份由后端维护策略决定，至少应关注：

- 用户数据。
- 内容数据。
- 评论和关系数据。
- 健康记录数据。
- 文件资源。
- AI 会话或知识库数据。

维护建议：

- 正式环境变更前应确认数据库和对象存储备份策略。
- 删除内容、清理文件、迁移健康数据等操作应先在测试环境验证。
- 涉及隐私数据的备份和导出应控制访问权限。

## 11. 发布前检查清单

### 11.1 Web 管理端发布检查

- 依赖安装成功。
- `npm run lint` 通过或已确认剩余问题不影响发布。
- `npm run build` 成功。
- 登录、角色分流、审核、驳回、删除、内容管理、发布、上传流程通过测试。
- 接口地址指向正确环境。
- 浏览器控制台无关键错误。
- 无不应公开的调试日志或敏感信息输出。

### 11.2 Android App 发布检查

- Gradle Sync 成功。
- Debug 包可安装运行。
- Release 包可构建。
- 登录、注册、推荐、知识、广场、详情、评论、发布、AI、记录、分析报告、隐私、个人中心通过回归。
- AndroidManifest 权限符合实际功能。
- 接口地址指向正确环境。
- 第三方 SDK 依赖可用。
- 真机验证图片选择、视频播放、OCR、上传和 AI 流式回复。
- 无明显崩溃和严重 ANR。

### 11.3 文档发布检查

- 需求规格、功能设计、架构文档、使用手册、安装维护文档内容一致。
- 使用手册截图与当前页面一致。
- 安装命令和构建命令可执行。
- 敏感信息未写入交付文档。

## 12. 安全与隐私维护要求

- 不在日志中输出完整 Token。
- 不在公开文档中写入生产密钥。
- 不将用户健康记录用于无关展示。
- 私密图片和 OCR 中间结果应谨慎保存。
- AI 请求参数中如包含敏感信息，应尽量提示用户确认。
- 生产环境故障排查只保留最小必要日志。
- 开发、测试、生产环境的数据应隔离管理。

## 13. 常见维护场景

### 13.1 后端接口地址变更

处理步骤：

1. Web 端检查 `src/api` 相关封装和环境配置。
2. App 端检查 `ApiConfig.java`。
3. 重新验证登录和基础内容接口。
4. 验证依赖 Token 的发布、评论、记录和 AI 功能。
5. 更新相关文档。

### 13.2 新增内容分类

处理步骤：

1. 后端确认分类 ID、名称和展示位置。
2. Web 端更新分类映射和发布/管理页面。
3. App 端更新知识或广场分类入口。
4. 验证内容发布、审核、展示链路。
5. 更新功能设计和使用手册。

### 13.3 AI 接口调整

处理步骤：

1. 明确 SSE 事件格式是否变化。
2. App 端更新 `RagSseClient` 解析逻辑。
3. 验证 `meta`、`message`、`finish`、`error` 等事件。
4. 验证引用内容是否仍可跳转。
5. 更新架构文档和安装维护说明。

### 13.4 Android 依赖下载失败

处理步骤：

1. 检查网络和代理。
2. 检查 `google()`、`mavenCentral()`、`jitpack.io` 是否可访问。
3. 检查第三方健康 SDK Maven 仓库是否可访问。
4. 清理 Gradle 缓存后重试。
5. 若仍失败，记录依赖名称、版本、仓库地址和完整错误日志。

### 13.5 用户隐私问题排查

处理步骤：

1. 确认问题发生页面和操作路径。
2. 判断涉及文本、图片、健康记录、AI 咨询还是日志输出。
3. 检查是否存在不必要展示或上传。
4. 检查日志是否记录敏感内容。
5. 修复后进行隐私相关回归测试。

## 14. 维护原则总结

- 先确认环境，再排查应用。
- 先验证登录，再验证业务。
- 先验证接口，再排查页面。
- 先保护数据，再执行清理。
- 先在测试环境验证，再发布到正式环境。
- 涉及健康、隐私、AI 和文件上传的变更必须重点回归。

### 7.3 生产环境部署

**构建检查**：
```bash
ls -lh dist/
# 确认 index.html 和 assets 目录存在
```

#### 7.3.2 Nginx 部署

**步骤 1：复制文件**

```bash
sudo mkdir -p /var/www/athena-rag-frontend
sudo cp -r dist/* /var/www/athena-rag-frontend/
```

**步骤 2：配置 Nginx**

创建配置文件 `/etc/nginx/sites-available/athena-rag`：

```nginx
server {
    listen 80;
    server_name your-domain.com;
    root /var/www/athena-rag-frontend;
    index index.html;

    # SPA 路由支持
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 代理到后端
    location /api/ragent {
        proxy_pass http://localhost:9090;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
        
        # SSE 长连接支持
        proxy_read_timeout 300s;
        proxy_connect_timeout 75s;
        proxy_buffering off;
        chunked_transfer_encoding on;
    }

    # 静态资源缓存
    location ~* \.(js|css|png|jpg|jpeg|gif|svg|ico|woff|woff2|ttf|eot)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # 安全头
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-XSS-Protection "1; mode=block" always;
    add_header X-Content-Type-Options "nosniff" always;
}
```

**步骤 3：启用配置**

```bash
sudo ln -s /etc/nginx/sites-available/athena-rag /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl restart nginx
```

#### 7.3.3 Docker 部署

**Dockerfile**：

```dockerfile
FROM node:18-alpine AS builder

COPY package*.json ./
RUN npm ci --only=production
```

```nginx
server {
```

### 7.4 故障排查

#### 问题 1：npm install 失败

**现象**：依赖安装报错

**解决方法**：
```bash
# 清理缓存
npm cache clean --force

# 使用国内镜像
npm install --registry=https://registry.npmmirror.com

# 删除 node_modules 重装
rm -rf node_modules package-lock.json
npm install
```

#### 问题 2：端口被占用

**现象**：`Port 5173 is already in use`

**解决方法**：
```bash
# Windows
netstat -ano | findstr :5173
taskkill /PID <PID> /F

# Linux/macOS
lsof -ti:5173 | xargs kill -9

# 或使用其他端口
npm run dev -- --port 5180
```

#### 问题 3：API 请求 404

**现象**：浏览器控制台显示 `404 Not Found`

**原因**：后端未启动或代理配置错误

**解决方法**：
```bash
# 测试后端是否可访问
curl http://localhost:9090/api/ragent/health

# 检查 vite.config.ts 代理配置
# 重启开发服务器
npm run dev
```

#### 问题 4：白屏或刷新 404

**现象**：生产环境访问路由白屏或 404

**原因**：Nginx 未配置 SPA 路由

**解决方法**：确保 Nginx 配置包含：
```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

#### 问题 5：SSE 连接中断

**现象**：消息流式输出突然停止

**原因**：Nginx 默认超时时间太短

**解决方法**：
```nginx
location /api/ragent {
    proxy_read_timeout 300s;
    proxy_connect_timeout 75s;
    proxy_buffering off;
}
```

#### 问题 6：Token 失效

**现象**：频繁跳转到登录页

**原因**：Token 过期或 localStorage 被清除

**解决方法**：
1. 重新登录
2. 检查后端 Token 有效期配置
3. 检查浏览器是否禁用 localStorage

#### 问题 7：文件上传失败

**现象**：上传文档时提示失败

**原因**：文件过大或后端限制

**解决方法**：
1. 检查文件是否超过 50MB
2. 检查后端 `spring.servlet.multipart.max-file-size` 配置
3. 检查 Nginx `client_max_body_size` 配置

```nginx
client_max_body_size 100M;
```
